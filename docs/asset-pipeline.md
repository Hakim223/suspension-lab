# 3D asset pipeline (Blender → GLB)

The app ships with **procedural, illustrative models** generated in code. Each important part is an
independently named node, so properly modelled Blender assets can replace them **part by part**,
without changing application code. The replacement path is covered by an automated test that exports
every procedural model to GLB, re-imports it through the GLB loader and checks that all parts bind by
name and move identically (`frontend/src/three/rig/glbRoundtrip.test.ts`), and by an e2e test that
loads GLB files over HTTP (`?model=glb`).

## Start from the reference templates

```bash
npm run glb:export-reference -w frontend        # writes frontend/public/models/reference/*.glb
```

Import a reference GLB into Blender (File → Import → glTF 2.0). It already has the correct names,
pivots, scale and design pose. Replace the geometry of each object with your detailed mesh while
keeping the **object name, origin and transform**. (The reference files are regenerated by every
production build and are not committed.)

List the node names a model needs:

```bash
npm run glb:expected -w frontend -- macpherson
```

## Conventions (must follow)

| Rule | Details |
|---|---|
| Units / axes | Metres. Blender is Z-up; the glTF exporter converts to **+Y up** (`export_yup`). In app space: X = outboard **right**, Y = up, Z = forward, ground at Y = 0. |
| What to model | Only the **right-hand corner** (`R_*`) and **centre** parts (`C_*`). The left corner is mirrored automatically. `L_*` nodes in a file are ignored. |
| Naming | `R_<Part_Name>` / `C_<Part_Name>` exactly as listed by `glb:expected` (case-sensitive). Root may be `<Model>_Assembly`. Children of a part can have any name unless noted below. |
| Design pose | Export at ride height, wheels straight, nothing exploded. |
| Rigid parts | (arms, knuckle/hub carrier, wheel, hub, strut body, axle housing, trailing arm, stabilizer arm, mount, rack housing) — origin at the part's natural pivot exactly where the reference has it; **scale applied (1, 1, 1)**. |
| Stretch parts | (piston rod, tie rod, links, toe/upper links, Panhard rod, rack bar, coil spring) — origin at the **bottom end**, axis along **+Y**, modelled at **1 m length** (the app scales Y to the current length). A spring mesh stretched this way also scales wire thickness slightly; keep procedural springs if that matters. |
| Damper body (`R_Shock_Absorber`, `R_Shock_Absorber_Body`) | Origin at the lower eye, axis +Y, real length (not stretched). |
| Composite parts with addressed children | Keep these **procedural** (omit from the GLB) unless you replicate the structure: `C_Stabilizer_Bar` and `C_Torsion_Beam` (N segment groups with custom property `u` ∈ (0,1)), `*_Stabilizer_Link_Joints` (children named `top`, `bottom`), `*_Link_Bushings` / `C_Panhard_Bushings` (children positioned by index), `R_Strut_Mount` child `rubber` (optional, squashed in the worn-mount simulation). |
| Materials | PBR metallic-roughness. Each part should use its own material instances (the app clones them anyway for highlighting). Avoid emissive in source materials (emissive is used for selection). |
| Context geometry | Chassis/body brackets (`*_Strut_Tower`, `*_Frame`, `C_Subframe`, …) are optional; keep them light. |

## Performance budget (per model, for mid-range Android tablets)

| Item | Target |
|---|---|
| Triangles | ≤ 60k total (procedural models: 10–31k) |
| Draw calls | ≤ 150 meshes (merge meshes that share a material within one part) |
| Textures | Prefer none (flat PBR). If used: ≤ 1024², KTX2/WebP, shared atlases |
| File size | ≤ 1.5 MB per GLB after compression |

## Export settings (Blender 3.6 / 4.x)

File → Export → glTF 2.0:

- Format: **glTF Binary (.glb)**
- Include: Selected/Visible objects, **Custom Properties** (extras)
- Transform: **+Y Up**
- Data → Mesh: Apply Modifiers ✓, UVs ✓, Normals ✓; Vertex colours off unless used
- Animation: off (the app animates parts procedurally)

Or run the helper which checks naming/scale and exports with these settings:

```bash
npm run glb:expected -w frontend -- macpherson > expected_macpherson.txt
```

```bash
blender my_macpherson.blend --background --python tools/blender/export_suspension_glb.py -- --out frontend/public/models/macpherson.glb --expected expected_macpherson.txt
```

## Compression

The loader supports **meshopt** compression (decoder bundled, no extra hosting). Compress with
[gltfpack](https://meshoptimizer.org/gltf/), keeping node names and materials:

```bash
gltfpack -i macpherson.glb -o macpherson.opt.glb -cc -kn -km
```

`-kn` keeps node names (required), `-km` keeps materials. Draco is not configured (it needs separately
hosted decoder files); use meshopt instead. If you add KTX2 textures, configure `KTX2Loader` with a
hosted transcoder in `frontend/src/three/rig/glbSource.ts`.

## Validate and enable

```bash
npm run glb:validate -w frontend -- frontend/public/models/macpherson.glb macpherson
```

Exits non-zero if a selectable part is missing. Then set `glb: 'macpherson.glb'` in
`frontend/src/three/models/registry.ts`. Files are served from `/models/` by default or from
`VITE_MODEL_BASE_URL` (CDN / object storage; enable CORS `GET` for the frontend origin and serve with
`Content-Type: model/gltf-binary`). The procedural model shows instantly and is swapped for the GLB
once it has downloaded; any missing nodes are logged to the console and filled procedurally.
